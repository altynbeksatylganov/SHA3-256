cryptographic hash function

SHA3-256

step 1 / foundation

What is a hash?

Imagine a machine that takes any message and creates a short digital fingerprint for it. That fingerprint is called a hash.

Core idea

You put data inside, SHA3-256 mixes it, and you get a fixed 256-bit digest. The digest helps recognize the data, but it does not reveal the original message.

try it yourself

your message→SHA3-256→fingerprint

Change even one letter. The fingerprint changes completely, but its length stays the same.

important difference

Hashing is not encryption

Encryption can be reversed with a key. Hashing is one-way.

Encryption

message+key→ciphertext
ciphertext+key→message

Encryption hides data and can recover it with the correct key.

Hashing

message→hash digest
hash digest↛message

SHA3-256 creates a fingerprint. It cannot be decrypted back.

Defense phrase: “SHA3-256 does not encrypt. It hashes data into a fixed fingerprint.”

step 2

Text becomes bytes

SHA3-256 does not process letters directly. First, the message is encoded as bytes. For normal text, the browser uses UTF-8.

Example

Every character is converted into a byte value. For example, “hello” becomes 68 65 6c 6c 6f. Your input on the right is converted live.

step 3

Padding

Padding adds extra bytes after the real message so SHA3 can process a complete 136-byte rate block and clearly know where the message ends.

Why padding?

Most messages are not exactly 136 bytes long. Padding completes the block before it goes into the sponge.

Padding bytes

06 marks SHA3 padding, 00 fills empty space, and 80 closes the padded block.

main algorithm

Sponge construction

Message blocks are XORed only into rate. Then the full state — rate plus capacity — enters Keccak-f.

What happens now?

Message bytes are absorbed through XOR with the rate part.

absorbing / preview

inside f

Keccak-f[1600]

Keccak-f[1600] is the permutation inside SHA3. It mixes the 1600-bit internal state through 24 rounds.

State structure

State = 5×5 lanes. Each lane = 64 bits. Therefore 25 × 64 = 1600 bits.

θ thetaρ rhoπ piχ chiι iota

operation 1 / 5

Theta θ

Theta mixes columns. It calculates column parity and XORs it into neighboring columns.

Simple meaning

One column starts affecting other columns. This spreads information across the state.

C[x] = XOR of column → D[x] → A[x,y] XOR D[x]

operation 2 / 5

Rho ρ

Rho rotates bits inside each 64-bit lane by different offsets.

Simple meaning

Bits stay in the same lane, but their positions rotate.

Pi π

Pi moves lanes to new positions in the 5×5 state.

Simple meaning

Whole lanes are rearranged across the state matrix.

operation 4 / 5

Chi χ

Chi is the nonlinear step. It changes each bit using two neighboring bits in the same row.

Why important?

Nonlinearity makes the transformation harder to reverse or predict.

operation 5 / 5

Iota ι

Iota XORs a round constant into lane A[0,0].

Simple meaning

Each round gets a different constant, so rounds are not symmetric copies.

final algorithm step

Squeezing

After all message blocks are absorbed, SHA3 squeezes output from the rate part. SHA3-256 needs 32 bytes.

Why 32 bytes?

256 bits = 32 bytes. The digest is usually shown as 64 hex characters.

examples

Where SHA3-256 is useful

File integrity

You download a file and compare its SHA3-256 hash with the official hash.

Digital signatures

Hash the document first, then sign the hash.

Data fingerprint

Use a short fixed digest to identify data.

Password warning

Do not store plain SHA3-256(password) in real systems.
